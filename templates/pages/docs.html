{{ _('A generator is a trusted Python package that the platform runs not on itself but on the analyst\'s machine: the browser starts Python in WebAssembly, reads the chosen folder through the system file access and sends up only the result — a finished HTML and its data files. The source Excel workbooks never leave the computer.') }}

{{ _('The analyst presses Run, picks a folder and gets a new version of the report. Your work is one zip archive.') }}

{{ _('what is in the bundle') }} 
{{ artifacts.bundle }}
02

{{ _('The contract: three functions and one rule about memory') }}

{{ _h('The engine opens a session, hands over the files {b}one at a time{b_} and asks for the result. After add_file returns, only aggregates may remain of a file: collecting frames in a list and concatenating them in finish() is forbidden — on a year of data the naive version hit the tab\'s ceiling (~2.75 GB), while the disciplined one held 468 MB flat.', b='', b_='') }}

{{ _('the engine contract') }} 
{{ artifacts.contract }}
  • {{ _h('{b}Determinism.{b_} The same inputs give byte-identical outputs: sort anything that comes out of the OS\'s sets and dictionaries, fix the column order, never bake the generation time into the data. The equivalence gate and an honest cache both stand on this.', b='', b_='') }}
  • {{ _h('{b}No input or output{b_} outside out_dir, cache_dir and the paths you are handed. No network, no threads, no subprocesses — WebAssembly has none of them, and the same code must keep working in plain CPython, because that is where it is tested.', b='', b_='') }}
  • {{ _h('{b}progress(stage, done, total, msg){b_} crosses the worker boundary. Call it once per file and once per major phase, never inside a loop over rows.', b='', b_='') }}
  • {{ _h('{b}The generator never sees folders.{b_} An analyst may connect up to eight of them; the engine hands over a flat union, so classify files strictly by name.', b='', b_='') }}
03

{{ _('manifest.json — the contract the platform checks for you') }}

{{ _('An unknown top-level key is a registration error: a typo in a contract has to be visible at once, not a month later on somebody else\'s machine. Declared inputs are not documentation: the engine reads exactly the files that match, and the platform builds the lineage map out of them.') }}

05

{{ _('Lineage: which folder the number came from') }}

{{ _('Every run records which folders were connected, which files were read, which sheets and columns were opened — and how that differs from what the manifest declared. The result is a graph: folder → pattern → sheet → generator → output → report. This is the answer to «where does this number come from», a question that usually has none.') }}

06

{{ _('Checks that travel with the calculation') }}

{{ _h('The manifest declares checks on the content of columns — {c}not_null{c_}, {c}unique{c_}, {c}range{c_}, {c}regex{c_}, {c}enum{c_}, {c}known_values{c_} — and the platform evaluates them on every run: the freshness of a source, a change in the number of rows, a column that went away, new values against a lookup table. A finding carries its own id, so «the same problem» is recognised across runs and a decision already made («we know, it is meant to be like that») does not have to be made again.', c='', c_='') }}

07

{{ _('Lookup tables: one mapping for the whole platform') }}

{{ _('Customer codes, the mapping of outlets to territories — what used to live as a hard-coded dictionary inside the code. Declare a lookup table as an input in the manifest: the platform creates it for you, keeps its versions, shows who is responsible for it and which values found no match. Whoever is responsible updates it — with no new version of your bundle.') }}

08

{{ _('semantics.json — and the report can be asked questions in plain language') }}

{{ _('An optional file next to the manifest describes what the report means: canonical tables, views, metrics with their formula, rules and a glossary. The platform validates it against empty typed tables at registration time, so a typo in a column name is an error for the author, not an empty answer for the user.') }}

{{ _h('What that buys: the question «what was service level by chain in July» turns into SQL written by {b}the engine, from your own formula{b_}, and that SQL is shown before any number appears. The model here picks the cut, it does not do the counting: cell values never enter a request to a model.', b='', b_='') }}

{{ _('The boundary worth knowing by heart.') }} {{ _('Only names and descriptions travel into the request to the model — of tables, of columns, of metrics. Not one cell of your data crosses that boundary: the calculation runs in the browser or on the platform\'s own server, and the model works with definitions.') }}

{{ _('Weight and speed: putting a heavy report on a diet') }}{{ _('the most common reason for «it is slow»') }}

{{ _h('The server hands a report over in a fraction of a millisecond — all the time the reader sees goes into transferring and parsing the HTML in their browser. {{ _('The typical «giant» is a small amount of visualisation code plus megabytes of JSON inside the markup.
